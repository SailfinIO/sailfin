## Fixture work removed

`run_cache_flags_test.sfn` now checks the cold default output in its existing
compatibility invocation and checks both warm trace assertions plus
`--no-cache` within one fixture lifecycle. This removes four nested `sfn run`
calls while keeping the `--no-cache`, `--clean` cache, and `--clean`
staged-tree assertions.
The private `--clean` fixture retains its original two warm runs. The
installed 0.12.0 seed writes cache schema v2 and cannot validate its v3
assertion; the edited file passed with the checkout's self-hosted compiler.

`runtime_demand_driven_sources_test.sfn` checks the staged module ceiling on
the same print-only build that proves crypto is absent. Its reused-scratch
case now runs the net-demanding binary before narrowing the staged set, so
the separate build of that identical net fixture is gone. These changes
remove two nested builds while retaining the manifest, sub-effect,
escape-hatch, diagnostic, and pruning assertions.

Local targeted verification used `sfn dev bootstrap build` followed by
`build/bin/sfn.exe test` on both edited files with `--jobs 2`. All four
cache-flag cases and all six runtime-gate cases passed. These local durations
are not directly comparable with the CI run's per-file times because the
compiler binary, cache state, and concurrent load differ.

## Post-merge CI and nightly split

After the first timing PR merged, [CI run 36431294150](https://github.com/SailfinIO/sailfin/actions/runs/36431294150)
still took 51.6 / 54.1 / 61.8 / 58.9 minutes for Windows e2e-a/b/c/d.

refresh and two fixture reductions were insufficient for a short PR loop.

Twenty-eight exhaustive CLI, cache, toolchain, and platform test files now
live in `compiler/tests/nightly`. They are 28 of the 410 e2e files in this
run, but account for 6,942 of 17,093 deduplicated Windows e2e file-seconds
(41%). The corresponding measured shares are 3,592 of 8,680 file-seconds
(41%) on macOS arm64 and 1,987 of 4,374 (45%) on Linux arm64. These are
summed file times from the run's completed JSONL sidecars; they are not
wall-clock savings forecasts. The new nightly workflow runs the moved files
on Linux, macOS, and Windows independently of the fixed-point self-host
nightlies, which can fail or reach their job cap before their test steps.

PR coverage still includes workspace resolution and member declarations;
user-config parsing and effect boundaries; toolchain gates and smaller CLI
cases; build and test cache unit tests; runtime source gates; and the rest
of the e2e suite. Changes to a nightly scenario should run its individual
file in the PR's verification commands. The first CI run of this split will
provide the actual new shard wall times and reveal whether another cut is
needed.
