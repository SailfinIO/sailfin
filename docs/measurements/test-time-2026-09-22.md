## Changes supported by the evidence

1. **Restore Windows time-weighted sharding.** The committed TSV had no
   line-ending rule. A Windows checkout with `core.autocrlf=true` produced
   CRLF; the native decimal parser rejected every row. Reproduced locally
   with the run's compiler: `dev shard cover` reported no usable table;
   converting only its line endings to LF restored weighted coverage.
   The run's Windows e2e-d file set exactly matched the alphabetical
   fourth-of-four partition after excluding nested scratch fixtures.
   Pin `*.tsv` to LF and test the real checked-out table's readability.
2. **Include Windows measurements.** The aggregator recognized only Unix
   targets and Unix filenames, so Windows uploads were ignored. Accept both
   layouts and exclude absolute nested-runner paths before deduplication and
   normalization. Refresh the table from this run's three measured targets.
   The old table was from August 31 and lacked 65 of today's 944 ordinary
   test files. Historical rows for moved files are harmless: discovery, not
   the weight table, defines the runnable inventory.
3. **Move exhaustive compiler parity to nightly.** This file builds the
   entire compiler twice. Keep its assertions intact under
   `compiler/tests/soak` and explicitly run it in both nightly self-host
   workflows and the scheduled Linux arm64 soak. Keep small-program work-directory and staging-equivalence
   coverage on every PR. This removes 13–19 minutes of measured per-file
   work per measured host, but shifts detection of compiler-scale path
   parity regressions to nightly/manual verification.

No language/runtime regression tests were deleted. No memory budgets or
per-file concurrency limits were increased. A fresh CI run is needed to
measure the combined wall-time improvement; replaying old file durations
under a different partition is not a measured speedup.

## Next reductions, in priority order

- Profile repeated cold nested builds in `runtime_demand_driven_sources`,
  `target_flag_cache_key`, and cache suites. Windows runtime-object cache
  paths default relative to cwd; tests with isolated working directories
  can rebuild the same runtime. Share immutable content-addressed objects
  only where cache isolation is not the behavior being tested. Keep cold,
  invalidation, and separate-target cache assertions genuinely isolated.
- Consolidate overlapping cold/warm/source-edit scenarios in
  `test_bin_cache_test.sfn` into one fixture lifecycle. Its standalone cold
  case and the cold setup in its warm case duplicate work; retain all
  assertions and verify fewer actual compiler/link invocations.
- Replace full builds used solely to inspect configuration precedence or
  target selection with focused resolver tests, retaining representative
  subprocess/link checks. Do not remove cross-target ABI artifact coverage.
- Measure test compilation separately from execution before consolidating
  small source-inspection tests. Merely moving files from e2e to unit shifts
  shard load without removing compile cost.

Refresh weights again after these workload changes have been measured.
Adding shards alone is less attractive on macOS, where five runner slots
already constrain the grouped matrix.
